# 查询工作线程复用

常驻线程池默认启用，OpenMP 对照可用 `--no-persistent-query-workers` 复测。单条并行时调用线程处理第一个入口分片，小批时处理第一条查询。其余线程按需唤醒。本页使用 Linux futex 后端实测。[线程组选项](../../docs/configuration.md#查询调度)

## v2.2 端到端复测

本机 Core i7-12700KF、WSL 2、AVX-VNNI，关闭细粒度计时。同一进程使用当前 v2.2 构建，预热后交替关闭和启用常驻线程池，每档 10 轮。每轮查询 GIST1M 的 1,000 条或 SIFT1M 的 10,000 条。固定图拓扑、全邻居缓存、默认查询排序、绑核和零自旋。计时包含查询准备、PCA、排序、查图、重排和写回。

GIST1M 使用 PCA128、SIFT1M 使用 PCA64，两者均用 UINT4 查图与粗排。单线程、小批和整批用 GIST1M 的 `L=400 / beam=6 / refine_max=400` 或 SIFT1M 的 `L=128 / beam=8 / refine_max=120`，FP32 精排 Top40。单条并行沿用 [v2.1 的 6／8 线程参数](../v2.1experiments/README.md#测试方式) 和每线程 FP32 Top16。混合请求按单条、Batch 6、Batch 16 循环，共用单条 6 线程的搜索参数。

表中为 OpenMP → 常驻池的中位 QPS / QPS/thread，变化取同轮 QPS 比值的中位数。单条按实际线程数折算，批量和混合档按 16 线程预算折算。

| 请求 | GIST1M QPS / QPS/thread | 变化 | SIFT1M QPS / QPS/thread | 变化 |
| --- | ---: | ---: | ---: | ---: |
| 单条，1 线程 | 3,061 / 3,061 → 3,069 / 3,069 | −0.6% | 13,261 / 13,261 → 13,224 / 13,224 | −0.1% |
| 单条，6 线程 | 5,157 / 859 → 6,236 / 1,039 | +22.2% | 9,093 / 1,516 → 12,813 / 2,135 | +40.6% |
| 单条，8 线程 | 4,331 / 541 → 5,499 / 687 | +28.4% | 7,210 / 901 → 11,021 / 1,378 | +51.7% |
| Batch 6，16 线程预算 | 8,051 / 503 → 10,337 / 646 | +29.1% | 17,731 / 1,108 → 40,577 / 2,536 | +128.3% |
| Batch 16，16 线程预算 | 13,309 / 832 → 14,079 / 880 | +3.8% | 39,949 / 2,497 → 54,117 / 3,382 | +36.7% |
| 单条／Batch 6／Batch 16 交替 | 5,714 / 357 → 7,220 / 451 | +25.7% | 14,617 / 914 → 33,972 / 2,123 | +137.4% |
| 整批，16 线程 | 20,307 / 1,269 → 20,169 / 1,261 | −0.6% | 159,140 / 9,946 → 162,416 / 10,151 | +0.1% |

单条 6 线程的请求 P95 从 GIST1M 的 275 降到 219 µs、从 SIFT1M 的 143 降到 97 µs。Batch 6 的 P95 分别从 890 降到 728 µs、从 414 降到 186 µs。整批两组均走 OpenMP，吞吐基本持平。

所有轮次的最低 Recall@10 为 GIST1M 99.060%、SIFT1M 99.078%。单条 1 线程及固定批量档的 Top10 ID 与 FP32 距离逐轮一致。

## 单条与小批共用线程组

本机 AVX-VNNI，使用同一张图、全邻居缓存、16 线程预算及默认零自旋。GIST1M 用 PCA128，SIFT1M 用 PCA64。小批和整批分别使用 GIST1M 的 `L=400 / beam=6 / refine_max=400` 和 SIFT1M 的 `L=128 / beam=8 / refine_max=120`。混合跑法按单条、Batch 6、Batch 16 循环，整轮用初版的单条 6 线程参数。各档交替跑 8 轮。表内是各轮 QPS 的中位数，变化按同轮配对计算。

| 请求 | GIST1M 初版 → 共用 QPS | 变化 | SIFT1M 初版 → 共用 QPS | 变化 |
| --- | ---: | ---: | ---: | ---: |
| 单条 6 线程 | 6,205 → 6,220 | +0.7% | 12,216 → 12,491 | +1.2% |
| 单条 8 线程 | 5,397 → 5,365 | +3.5% | 10,784 → 10,750 | +1.0% |
| Batch 6 | 7,942 → 11,214 | +37.9% | 17,707 → 39,563 | +120.9% |
| Batch 16 | 13,899 → 15,135 | +7.6% | 39,722 → 54,250 | +38.2% |
| 单条／Batch 6／Batch 16 交替 | 6,792 → 7,249 | +7.4% | 24,456 → 34,815 | +41.8% |
| 整批 | 20,756 → 20,950 | +0.7% | 158,258 → 157,780 | +0.1% |

所有档位的 Recall@10 均超过 99%。只含批量请求的各档，Top10 ID 和距离逐轮一致。混合档每轮的 Recall@10 至少为 GIST1M 99.71%、SIFT1M 99.64%。SIFT1M 连续运行 100 组混合请求，共用组创建 15 个工作线程，由调用线程补足第 16 个席位。

## 整批动态领块

沿用上面的整批参数。同一进程预热后交替跑 20 轮，对照 OpenMP 动态调度和实验版常驻组。两者都每块领取 4 条查询。QPS 和 QPS/thread 取中位数，变化取同轮 QPS 比值的中位数。

| 数据集 | 查询数／批 | OpenMP QPS / QPS/thread | 常驻组 QPS / QPS/thread | QPS 变化 | Recall@10 |
| --- | ---: | ---: | ---: | ---: | ---: |
| GIST1M | 1,000 | 19,571 / 1,223 | 19,612 / 1,226 | +0.23% | 99.060% |
| SIFT1M | 10,000 | 151,244 / 9,453 | 149,867 / 9,367 | −0.17% | 99.122% |

两个数据集都是常驻组赢 10 轮、OpenMP 赢 10 轮。Top10 ID 和距离逐轮一致，整批吞吐在实测波动范围内。

## 单条线程组初版

本机 AVX-VNNI、固定图、全邻居缓存、`OMP_PROC_BIND=close` 和默认零自旋。连续单条请求用 [v2.1 的 6／8 线程搜索参数](../v2.1experiments/README.md#测试方式)，OpenMP 和固定组交替测 8 轮。混合档交替提交单条和 Batch 6，单条用 6 线程，批量预算 16，两种请求均采用单条 6 线程对应的搜索参数。QPS/thread 按表内线程预算折算。变化取同轮 QPS 比值的中位数，Recall@10 取两种派发的最低值。

| 数据集 | 请求 | OpenMP QPS / QPS/thread | 固定组 QPS / QPS/thread | QPS 变化 | 请求 P95（µs） | 最低 Recall@10 |
|---|---|---:|---:|---:|---:|---:|
| GIST1M | 单条 6 线程 | 5,130 / 855 | 6,266 / 1,044 | +21.5% | 276.7 → 227.0 | 99.090% |
| GIST1M | 单条 8 线程 | 3,839 / 480 | 5,280 / 660 | +35.7% | 338.4 → 252.8 | 99.060% |
| GIST1M | 单条／Batch 6 交替 | 3,420 / 214 | 5,024 / 314 | +45.2% | 1,949.4 → 1,345.2 | 99.600% |
| SIFT1M | 单条 6 线程 | 8,323 / 1,387 | 12,499 / 2,083 | +49.6% | 196.2 → 108.3 | 99.096% |
| SIFT1M | 单条 8 线程 | 6,777 / 847 | 10,580 / 1,322 | +55.1% | 232.8 → 128.2 | 99.093% |
| SIFT1M | 单条／Batch 6 交替 | 6,465 / 404 | 14,169 / 886 | +123.6% | 966.0 → 458.7 | 99.585% |

6 线程单条的计时构建对照中，最晚完成到调用方返回的时间由 GIST1M 的 47.77 µs 降到 13.78 µs，由 SIFT1M 的 39.63 µs 降到 13.87 µs。SIFT1M 单独运行 100 组单条／Batch 6 交替请求时，扣除图装配后，OpenMP 调用 `pthread_create` 1,015 次，固定组模式下两个线程组共调用 20 次。

间隔约 1 ms 的单条请求每轮抽样 256 条。6 线程的查询 P95 在 GIST1M 从 291.4 降到 276.5 µs，在 SIFT1M 从 174.2 降到 143.4 µs。精度门槛使用上表的完整查询集核对。

## 跨平台验证

在 Linux 本机分别编译 futex 和条件变量后端，两种构建各通过 101 项仓库测试。Windows x64 原生测试覆盖线程池模块，在 2、6、8、16 个线程席位之间切换，共执行 2,000 次派发，并验证调用线程和工作线程抛出异常后线程池仍能复用。上面的 QPS 均来自 Linux。
