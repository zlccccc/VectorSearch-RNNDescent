# 小批查询准备门槛

## 代码改动

v2.0 在批量超过 16 条时并行准备。量化和 FP32 范数也分别在批量与向量维度的乘积超过 2,048 和 8,192 时并行。

v2.1 用 `parallel_query_preparation` 统一了条件。批量超过 16 条、OpenMP 当前线程数上限大于 1，且平均每线程至少 4 条查询时，才并行准备。其余情况由调用线程完成查图量化、粗排量化和 FP32 查询范数。[共用门槛](../../solution/rnndescent/discomputer/MyDistanceComputer.h#L69) · [量化调用处](../../solution/rnndescent/discomputer/quantized/QuantizedDistanceComputer.h#L148) · [范数调用处](../../solution/rnndescent/discomputer/flat/FlatDistanceComputer.h#L61)

## 单项复测

复用总表的固定图、启动配置和查询输入，在同一个 v2.1 测试二进制里切换准备门槛，每档交替测 6 轮。各档均开启 PCA 批内排序。GIST1M 和 SIFT1M 的 Recall@10 分别为 99.060% 和 99.122%，同轮的 Top10 ID 和 FP32 距离一致。[测试方式](README.md#测试方式)

表中为中位 QPS / QPS/thread，箭头为对照门槛 → 当前门槛，括号为同轮 QPS 比值的中位变化。

| 对照门槛 | 批量 | 线程 | GIST1M | SIFT1M |
|---|---:|---:|---:|---:|
| 旧维度与批量门槛 | 6 | 16 | 5,679 / 355 → 7,750 / 484（+36.5%） | 16,408 / 1,026 → 17,157 / 1,072（+2.8%） |
| 旧维度与批量门槛 | 16 | 16 | 9,096 / 569 → 12,446 / 778（+38.6%） | 38,099 / 2,381 → 37,303 / 2,331（−1.8%） |
| 只要求批量超过 16 | 17 | 6 | 8,939 / 1,490 → 10,271 / 1,712（+17.9%） | 23,009 / 3,835 → 35,662 / 5,944（+59.2%） |
| 只要求批量超过 16 | 32 | 16 | 10,199 / 637 → 12,829 / 802（+30.1%） | 20,721 / 1,295 → 39,957 / 2,497（+86.9%） |
| 移除 16 条下限 | 8 | 2 | 4,964 / 2,482 → 5,077 / 2,539（+2.3%） | 17,525 / 8,763 → 21,352 / 10,676（+20.2%） |
| 移除 16 条下限 | 12 | 3 | 6,760 / 2,253 → 7,217 / 2,406（+6.2%） | 23,006 / 7,669 → 29,712 / 9,904（+33.7%） |
| 移除 16 条下限 | 16 | 4 | 8,106 / 2,026 → 8,891 / 2,223（+7.0%） | 26,413 / 6,603 → 39,882 / 9,970（+46.3%） |

SIFT1M 的 Batch 6 和 16 在旧规则下也串行准备。保留 16 条下限改善了 2–4 线程的小批吞吐，每线程至少 4 条的条件在 Batch 17／6 线程和 Batch 32／16 线程下都有收益。
