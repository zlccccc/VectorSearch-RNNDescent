# 算法与数据流

入口程序由 [main.cpp](../main.cpp) 调用 [BenchmarkRunner.h](../benchmark/BenchmarkRunner.h)。后者负责读取数据、选择参数和计时，再通过 [Solution](../solution/solution.cpp) 使用索引。

~~~mermaid
flowchart TD
    B[原始 FP32 底库] --> P{启用 PCA}
    P -->|开启| T[PCA 训练与底库投影]
    P -->|关闭| G[量化并迭代建图]
    T --> G
    G --> R[裁剪邻居与 BFS 重排]
    R --> I[按 BFS 顺序量化底库]
    I --> C[邻接表与可选邻居向量缓存]
    Q[原始 FP32 查询] --> V[按配置投影并量化]
    C --> S[图搜索与候选合并]
    V --> S
    S --> F[将候选 ID 映射回原始行]
    B --> E[原始 FP32 精排]
    Q --> E
    F --> E
    E --> O[Top K 原始 ID 与平方 L2]
~~~

**建图由迭代更新、反向边处理和重排组成。**

[RNNDescent](../solution/rnndescent/RNNDescent.h) 按 `S` 生成初始随机邻居，通过量化平方距离比较候选。`T1` 控制外层迭代次数，每轮内执行 `T2` 次邻居更新，外层轮次之间处理反向边并用 `R` 限制候选规模。结束后按距离裁剪到 `K0`，邻接 ID 存储补齐为四条一组。

查询入口决定 BFS 的起点顺序。重排后，`search_from_ids` 把图节点 ID 映射回原始底库行号。量化码从原始或 PCA 投影后的矩阵直接写入 BFS 顺序的存储。默认精排保存原始 FP32 底库指针及平方范数。

**PCA 改变建图和查图的空间，精排保留原始空间。**

[PCAProjection](../solution/rnndescent/PCAProjection.cpp) 训练时最多采样 `1000 * 输入维度` 条向量，采用固定随机种子 1234。它计算均值和协方差，使用 OpenBLAS 的 `ssyrk` 与 LAPACK 的 `dsyev_` 求主方向。训练条数小于输入维度时求较小的 Gram 矩阵，再恢复并归一化主方向。

采样通过行 ID 记录顺序，按最多 16,384 行收集一个 FP32 批次，再累加协方差。GIST1M 的 960 维训练批次约占 60 MiB。分块累加会改变浮点求和顺序，投影差异通过目标数据的 Recall 验证。

底库与查询使用相同的投影矩阵和中心化偏置。投影通过 OpenBLAS 的 `sgemm` 完成。构建完图后释放临时底库投影矩阵，保留投影参数和查询工作缓冲。数学库依赖由 OpenBLAS 提供。

PCA 查询缓冲按实际批量增长并复用容量。

**查询批次中的每条查询由一个 OpenMP 工作线程处理。**

先对入口向量批量算距并保留前 `search_L` 个候选，再按分数选择未展开节点。每次最多展开 `beam_size` 个节点，对其邻居四路算距，再结合队尾阈值和访问表筛选新候选。

新候选排序后，局部 lambda 将它们从尾部逐项合并回候选池。先检查最大可保留数量，能全收时直接合并，否则二分确定保留数量。只搬动受影响的后缀，距离相同时旧候选排在前面。合并返回最早改动位置，供搜索继续处理新进入池中的节点。

每线程使用带轮次标记的访问表，在查询结束后推进标记。搜索持续到有序候选池中的节点均已展开，最后映射回原始 ID，并计算前 `refine_max` 个候选的 FP32 距离，选择并排序 Top K。

各阶段的参数、CLI 覆盖方式和数据集预设见 [参数配置](configuration.md)，可用参数由 [CLI 定义](../benchmark/BenchmarkCLI.h) 给出。

**内存分配由原始数据、索引数据和工作缓冲共同构成。**

设底库行数为 `N`，原始维度为 `D`，查图补齐维度为 `stride`，线程数为 `T`，补齐后的总邻接数为 `E`。

| 部分 | 大小或分配方式 | 生命周期 |
|---|---|---|
| 原始 FP32 底库 | `4 * N * D` 字节 | 调用方持有，覆盖索引使用时间 |
| 量化底库码与范数 | 约 `N * stride + 4 * N` 字节，另有逐维量化中心 | 索引持有 |
| 图 ID 映射 | `4 * N` 字节 | 索引持有 |
| 邻接 ID 池 | 至少 `4 * E` 字节，按节点增加对齐空间 | 索引持有 |
| 邻接表元数据 | 每节点的指针、跨度和计数，随 `N` 线性增长 | 索引持有 |
| 可选邻居缓存 | 按边复制量化码和范数，受邻居池预算约束 | 与邻接 ID 共用池 |
| 每线程访问表 | 约 `T * N` 字节 | 索引持有 |
| 查询与候选缓冲 | 随查询批量、入口数、候选池和 beam 大小变化 | 索引内复用 |
| 建图临时邻接表与反向边 | 随候选边数变化 | 建图期间 |
| PCA 训练样本、矩阵和底库投影 | 随训练样本数、原始维度和输出维度变化 | PCA 训练与建图期间 |

例如 GIST1M 的原始 FP32 底库约为 3.58 GiB，这部分由调用方持有。邻居缓存还会按边重复存储向量，所以预算为几 GiB 的邻居池会显著影响总占用。峰值内存还包含建图临时对象。

`IndexRNNDescent::reset` 释放图索引、精排计算器与 PCA，并清空 PCA 查询缓冲的内容。部分向量容量可继续复用，对象销毁时释放。进程结束后，操作系统仍可能保留已读数据文件的页缓存。测量进程内存时记录 RSS 和峰值 RSS，结合系统匿名页与文件缓存判断。

测距内核与缓存布局见 [测距实现](../solution/rnndescent/discomputer/README.md)，比较性能的记录方式见 [Benchmark 使用](../benches/README.md)。
