# 算法与数据流

入口程序由 [main.cpp](../main.cpp) 调用 [BenchmarkRunner.h](../benchmark/BenchmarkRunner.h)。后者负责读取数据、选择参数和计时，再通过 [Solution](../solution/solution.cpp) 使用索引。

`IndexRNNDescent` 负责组装 PCA、图索引和候选重排。`RNNDescent` 保留兼容外观，内部由 `GraphBuilder`、`GraphReorder` 和 `GraphSearcher` 分别负责建图、BFS 重排及查询初排。`CandidateReranker` 负责可选的量化粗排和最终 FP32 精排。查图和粗排各自在建索引时选择 DistanceComputer。模块职责见 [RNNDescent 模块说明](../solution/rnndescent/README.md)。

**建图由迭代更新、反向边处理和重排组成。**

[GraphBuilder](../solution/rnndescent/build/GraphBuilder.h) 按 `S` 生成初始随机邻居，通过量化平方距离比较候选。`T1` 控制外层迭代次数，每轮内执行 `T2` 次邻居更新，外层轮次之间处理反向边并用 `R` 限制候选规模。结束后按距离裁剪到 `K0`，邻接 ID 存储补齐为四条一组。

重复边合并时，只要任一副本标记为新边，合并结果就保留这个标志。邻居更新会跳过两条边均已处理过的候选对，因此新边标志会影响后续传播。

启用 [局部三跳筛边](../solution/rnndescent/build/GraphPruning.h) 后，每行在裁剪前检查前 `2 * K0` 个候选。每个节点的最近 `min(32, K0 / 2)` 条边作为保留前缀。替代路径由这些前缀组成，并且沿源点的候选排名递增。按能到达目标的不同首跳数给边打分，每行至多用较少替代路径的候选替换四条边。

重排以全部查询入口为起点，按邻接表顺序逐层遍历。入口点保留在行序开头，不可达点按原始行号追加到末尾。`search_from_ids` 把 BFS 图 ID 映射回原始底库行号，建图时用反向映射转换邻接 ID。量化码从原始或 PCA 投影后的矩阵直接写入 BFS 顺序的存储。默认精排保存原始 FP32 底库指针及平方范数。

**PCA 改变建图和查图的空间，精排保留原始空间。**

[PCAProjection](../solution/rnndescent/PCAProjection.cpp) 训练时最多采样 `1000 * 输入维度` 条向量，采用固定随机种子 1234。它计算均值和协方差，使用 OpenBLAS 的 `ssyrk` 与 LAPACK 的 `dsyev_` 求主方向。训练条数小于输入维度时求较小的 Gram 矩阵，再恢复并归一化主方向。

采样通过行 ID 记录顺序，按最多 16,384 行收集一个 FP32 批次，再累加协方差。GIST1M 的 960 维训练批次约占 60 MiB。分块累加会改变浮点求和顺序，投影差异通过目标数据的 Recall 验证。

底库与查询使用相同的投影矩阵和中心化偏置。投影通过 OpenBLAS 的 `sgemm` 完成。构建完图后释放临时底库投影矩阵，保留投影参数和查询工作缓冲。数学库依赖由 OpenBLAS 提供。

训练完成后，将带固定符号的归一化 Hadamard 旋转折入投影矩阵和偏置。输出维度为 2 的幂时旋转所有坐标，其余维度按从大到小的 2 的幂分块旋转，保留 PCA 空间的平方 L2 和输出维度。旋转在量化前分散主方向的能量，底库和查询共用一次矩阵投影。`PCAProjection` 按实际查询批量分配并复用内部投影缓冲。

**查询批次中的每条查询由一个 OpenMP 工作线程处理。**

先对入口向量批量算距并保留前 `search_L` 个候选，再按分数选择未展开节点。每次最多展开 `beam_size` 个节点，对其邻居四路算距，分数写入每线程的 64 字节对齐缓冲区。筛选结合队尾阈值和每线程的 [候选位图](../solution/rnndescent/search/CandidateBitmap.h) 收集新候选。

每轮先算完邻居分数，记录各邻接行的 ID 指针和长度。随后按分数的顺序把 ID 复制到连续缓冲，再用本轮固定的队尾阈值整批筛选并按原顺序去重。队尾分数在排序合并时更新。

[邻居分数筛选](../solution/rnndescent/search/NeighborScoreFilter.h) 在 AVX-512 后端对少于 32 个邻居的行使用八路比较，达到 32 个时先处理十六路块，剩余可再处理一个八路块。AVX2 和 AVX-VNNI 使用八路 FP32 比较，AArch64 NEON 使用四路。建图展平时逐行把邻居数补到 4 的倍数，各路径按邻接表顺序收集严格低于阈值且尚未标记的新候选，收集到的候选数随查询变化。

x86 比较后剩余的四项走标量尾部。SIFT100K 同图单线程对照中，四路 SIMD 尾部的端到端配对 QPS 变化为 +0.26%，95% 区间为 −0.15% 至 +0.76%。

新候选排序后，局部 lambda 将它们从尾部逐项合并回候选池。先检查最大可保留数量，能全收时直接合并，否则二分确定保留数量。只搬动受影响的后缀，距离相同时旧候选排在前面。合并返回最早改动位置，供搜索继续处理新进入池中的节点。

建图结束时按底库点数预分配每线程的候选位图，每个 ID 占 1 bit。查询开始时清零并标记保留的入口，后续只标记首次通过阈值的候选。队尾分数只会收紧，落选或淘汰的 ID 以相同分数重现时无法再次通过严格小于队尾的阈值，因此标记可以保留到查询结束。

搜索持续到有序候选池中的节点均已展开，最后取出池内前 `refine_max` 项，原地交给 [CandidateReranker](../solution/rnndescent/search/CandidateReranker.h)。量化粗排启用时，按照单独配置的编码为原始维度建立距离计算器，直接按 BFS 顺序编码并用图 ID 算距。查图已经使用原始维度，且两阶段都采用 8 位编码时，可以复用图初排分数并省去第二份量化码。粗排通过 `nth_element` 留下 `fp32_refine_max` 项，至少保留 Top K。

选择 FP32 直排、将 `fp32_refine_max` 设为 0，或本次候选数已经在 FP32 预算内时，直接把整批图候选交给 FP32。映射回原始 ID 后，用原始 FP32 向量算距并选出 Top K。建索引时若最大候选数已在精排预算内，也无需分配粗排量化底库。

各阶段的参数、CLI 覆盖方式和数据集预设见 [参数配置](configuration.md)，可用参数由 [CLI 定义](../benchmark/BenchmarkCLI.h) 给出。

**内存分配由原始数据、索引数据和工作缓冲共同构成。**

设底库行数为 `N`，原始维度为 `D`，查图补齐维度为 `stride`，补齐后的总邻接数为 `E`。

| 部分 | 大小或分配方式 | 生命周期 |
|---|---|---|
| 原始 FP32 底库 | `4 * N * D` 字节 | 调用方持有，覆盖索引使用时间 |
| 量化底库码与范数 | 约 `N * stride + 4 * N` 字节，另有逐维量化中心 | 索引持有 |
| 原始维度的粗排量化码 | 8 位编码约 `N * round_up(D, SIMD块宽) + 4 * N` 字节，960 维 4 位编码为 `492 * N` 字节 | 仅在 PCA 与两阶段精排同时启用时保存 |
| 图 ID 映射 | `4 * N` 字节 | 索引持有 |
| 邻接 ID 池 | 至少 `4 * E` 字节，按节点增加对齐空间 | 索引持有 |
| 邻接表元数据 | 每节点的指针、跨度和计数，随 `N` 线性增长 | 索引持有 |
| 可选邻居缓存 | 按边复制量化码和范数，受邻居池预算约束 | 与邻接 ID 共用池 |
| 每线程候选去重表 | 每槽 4 字节，以容纳至多 `min(N, search_L + beam_size * 补齐后的最大邻接数)` 个 ID，槽位数向上取二的幂并保持负载不超过一半 | 索引内复用 |
| 查询与候选缓冲 | 随查询批量、入口数、候选池和 beam 大小变化 | 索引内复用 |
| 建图临时邻接表与反向边 | 随候选边数变化 | 建图期间 |
| PCA 训练样本、矩阵和底库投影 | 随训练样本数、原始维度和输出维度变化 | PCA 训练与建图期间 |

例如 GIST1M 的原始 FP32 底库约为 3.58 GiB，这部分由调用方持有。邻居缓存还会按边重复存储向量，所以预算为几 GiB 的邻居池会显著影响总占用。峰值内存还包含建图临时对象。

`IndexRNNDescent::reset` 释放图索引、精排计算器与 PCA。PCA 对象销毁时也释放查询投影缓冲。部分查询结果缓冲可继续复用，对象销毁时释放。进程结束后，操作系统仍可能保留已读数据文件的页缓存。测量进程内存时记录 RSS 和峰值 RSS，结合系统匿名页与文件缓存判断。

测距内核与缓存布局见 [测距实现](../solution/rnndescent/discomputer/README.md)，比较性能的记录方式见 [Benchmark 使用](../benches/README.md)。
